# Waystroke — одностраничный сайт-портфолио

Одностраничная витрина небольшой веб-студии: тёплый светлый фон,
выразительная типографика, тёмная секция «Дизайн» и один лаймовый акцент
(`#C8F054`). Мотив — тонкая линия, похожая на мазок кисти и путь.

## Стек

- **Angular 22.2.0** (стабильный релиз, standalone-компоненты, zoneless)
- Обычный CSS без UI-библиотек, шрифты локально через `@fontsource`
  (Inter 400–700, Playfair Display italic для акцентной строки)
- Без бэкенда и без внешних сервисов, кроме Cal.com (эмбед записи) и Telegram

## Команды

```bash
npm install        # зависимости
npm start          # дев-сервер: http://127.0.0.1:4200
npm run build:prod # production-сборка в dist/waystroke-studio/browser
npm run serve      # статический сервер собранного варианта (порт из PORT, по умолчанию 3000)
npm test           # unit-тесты (vitest)
```

## Секция «Дизайн»

Секция «Разные задачи. Разный характер.» — живая витрина того, как выглядят
**шесть независимых концептов для шести разных ниш**. Это **концепты, а не
клиентские проекты**: отзывы, клиенты, цифры результатов и ссылки на «готовые
проекты» к демо не придумывались.

Три пары сравнения:

| Пара | Концепты | Разный характер |
| --- | --- | --- |
| Музыка / Beauty | «СДВИГ» ↔ «miora» | чёрный фон, кислотный лайм, хром и винил против слоновой кости, антиквы и сетки товаров |
| Авто / Кофе | «ТОЧКА МОТОР» ↔ «крошка» | почти чёрный герой, наклонный гротеск и красный акцент против сливочных тонов, скруглений и меню с ценами |
| Fintech / Art | «saldo» ↔ «ВНЕ РАМКИ» | светлый дашборд с карточками и диаграммой против бумажного постера с крупным чёрным титулом |

- **«СДВИГ»** — музыкальный лейбл: заголовок «Звук вне правил.», обложки
  и релизы нарисованы только CSS/SVG, внешних картинок нет;
- **«miora»** — косметика: тёплая слоновая кость, крупная антиква, чипсы
  и витрина из трёх позиций;
- **«ТОЧКА МОТОР»** — автосервис: фото покрасочной камеры под затемняющей
  шторкой, скошенный заголовок «Точность, в каждой детали.», красный CTA и
  светлая полоса услуг 01 / 02 / 03 со штриховыми иконками;
- **«крошка»** — кофейня: антиква, фотография справа, стикер «свежая обжарка»
  и горизонтальное «Меню дня» с ценами;
- **«saldo»** — финприложение: левая панель, баланс со спарклайном, карта,
  кольцевая диаграмма расходов, операции и цели; все магазины и суммы вымышлены;
- **«ВНЕ РАМКИ»** — арт-выставка: бумага, плотный чёрный титул, рамка с
  геометрией, выходящей за её край, и программа разделов с куратором.

Каждый концепт лежит в своём файле (`concepts/<имя>.*`), общий только контракт:
корень `.mock` заполняет слой целиком, размеры считаются от контейнера через
`clamp()`/`cqw`, а на узком контейнере (≤ 700 px) container query складывает
макет в «мобильную версию». Оба слоя лежат в одной сетке (ячейка `1/1`), и
контейнер принимает высоту большего: ползунок не сжимает половины, а открывает
их обрезкой (`clip-path: inset()` на верхнем слое).

Механика сравнения (`design-demo.*`):

- над сценой — переключатель из трёх пар (кнопки с `aria-pressed`), при смене
  пары граница предсказуемо возвращается на 50 %;
- Pointer Events: нажатие точно по бегунку **и** в любом месте сцены сразу
  ставит границу и продолжает drag; мышь, касание и стилус работают одинаково,
  используется `setPointerCapture(pointerId)`, движение учитывает только
  активный `pointerId`, а `pointerup`/`pointercancel`/`lostpointercapture`
  корректно завершают жест (при `pointercancel` граница откатывается к
  значению на момент нажатия);
- drag продолжается за пределами сцены, значение клампится в 0…100;
- hit-area бегунка ≥ 44 px и совпадает с видимой линией, курсор `col-resize`,
  у рамки `touch-action: pan-y`, у бегунка `none` — вертикальная прокрутка
  страницы на телефоне не блокируется;
- изображения, декоративные слои и текст внутри концептов не перехватывают
  события (`pointer-events: none`, `draggable="false"`, `user-select: none`):
  нативный drag картинок невозможен, выделение текста не мешает;
- клавиатура и скринридер: `role="slider"`, `tabindex="0"`, актуальные
  `aria-valuemin/max/now`, `aria-valuetext`, `aria-label`, подсказка через
  `aria-describedby`, стрелки ±2 %, `Shift`+стрелки ±10 %, `PageUp/PageDown`,
  `Home/End` и заметный `:focus-visible`.

## Превью ссылки и индексация

Заголовок и описание сайта (в `<title>`, `description`, `og:*` и `twitter:*`
берутся из тех же строк):

- **title** — `Waystroke — студия веб-дизайна и разработки сайтов` (50 знаков):
  «студия» вместо личного профиля, дальше два главных запроса — веб-дизайн
  и разработка сайтов;
- **description** — 147 знаков: создание и разработка сайтов под заказ,
  веб-дизайн и UX/UI, адаптивная вёрстка и запуск, от структуры страниц до
  публикации. Без «лучших», «дешёвых», «№1» и «гарантированного результата»;
- **keywords** в `meta` намеренно нет: Google и Яндекс его не читают, а список
  мгновенно устаревает и тянет за собой правки.

Позиционирование в текстах тоже студийное: в первом экране — «Над проектом
работает наша команда», в блоке «Наша команда» — роли без числа участников
(`Web UX/UI Designer` и `Web Developer`). Количество сотрудников, отзывы,
рейтинги и цифры результата нигде не называются: этого нет на сайте, и
придумывать такое перед production нельзя.

Картинка для ссылок — `public/images/og-waystroke.png`, ровно **1200×630, PNG**
(собрана из тех же токенов и шрифтов Inter/Playfair, что и сайт: фон `#ece9df`,
тёмный текст, лаймовый акцент `#c8f054`, фирменный мазок линии). Читается и в
маленьком превью Telegram — проверено на уменьшении до 420 px и 200 px.

В `<head>` (`src/index.html`):

- `link rel="canonical"` → `https://waystroke.online/`;
- `meta name="robots"` → `index, follow, max-image-preview:large`;
- Open Graph: `og:type=website`, `og:site_name=Waystroke`, `og:locale=ru_RU`,
  `og:title`, `og:description`, `og:url=https://waystroke.online/`,
  абсолютный `og:image` + `og:image:type/width/height/alt`;
- Twitter Card: `summary_large_image` (+ `twitter:title/description/image`
  и `twitter:image:alt`);
- **Schema.org** (JSON-LD, `@graph`): `WebSite` и `ProfessionalService` с
  `sameAs` на Telegram и каталогом услуг `hasOfferCatalog` — четыре позиции с
  теми же ценами и сроками, что напечатаны в карточках услуг. Оценок и отзывов
  в разметке нет: выдумывать их нельзя, Google такие данные считает
  нарушением правил;
- `link rel="preconnect"` к `cloudflareinsights.com` — beacon грузится всегда,
  и раннее соединение срезает ~300 мс.

Все URL в метаданных абсолютные и ведут на `https://waystroke.online` — с
`<base href="/">` относительные пути в превью ломались бы.

- `public/robots.txt` — `User-agent: *`, `Allow: /`, ссылка на sitemap;
- `public/sitemap.xml` — единственный реально существующий адрес
  `https://waystroke.online/` (сайт одностраничный, якорей и роутинга нет,
  выдуманных маршрутов в карте нет);
- `public/yandex_6e99f680d7655231.html` — файл подтверждения Яндекс.Вебмастера.

### Иконка сайта

`favicon.svg` — та же метка, что и в шапке (лаймовая точка и линия), но без
полупрозрачной линии: на 16 px она не читалась. Растровые версии
(`favicon-16x16.png`, `favicon-32x32.png`, `favicon-48x48.png`) нарисованы из
того же SVG, `apple-touch-icon.png` — 180×180 для экрана «Домой» на iOS.
Все четыре файла квадратные, с одинаковым безопасным полем, и подключены явно
(`rel="icon"` с `sizes` и `rel="apple-touch-icon"`) — иначе Яндекс и Google
подставляют случайную иконку или вовсе её не находят.

`manifest.webmanifest` не нужен: это не PWA, нет устанавливаемого приложения и
нет экранов, которые пришлось бы кэшировать офлайн. По той же причине нет и
`theme-color` для конкретных медиазапросов — есть один общий, в тон фону.

### Иерархия заголовков

Ровно один `h1` (первый экран), дальше `h2` на каждую смысловую секцию
(«Дизайн», «Кейсы», «Услуги», «Как мы работаем», «Команда», «Условия работы»,
«Контакты») и `h3` внутри них (карточки услуг, роли). Блок этапов раньше
обходился одной надписью-меткой без заголовка — теперь это `h2` с тем же
классом `.label`, то есть вид не изменился, а структура документа стала
полной.

В начало страницы добавлена skip-ссылка «Перейти к содержанию» — она первая в
порядке табуляции и видна только в фокусе (`.skip-link` в `styles.css` был
написан ещё до её появления в разметке).

## Секция «Кейсы»

Публичных клиентских проектов у студии нет, а придумывать клиентов, отзывы и
цифры результата нельзя. Поэтому секция сделана данными, а не вёрсткой:

- `src/app/work/work.data.ts` — интерфейс `CaseStudy` и пустой `PROJECTS`;
- `src/app/work/work.html` — карточки по этим данным, а при пустом списке одна
  честная строка вместо пустых карточек;
- `src/app/work/work.css` — те же поверхности, что у карточек услуг
  (`--surface`, тонкая рамка, `--radius-md`).

Чтобы добавить реальный кейс: положить обложки в
`public/images/cases/<имя>.webp` (960 и 480 px, как у концептов) и дописать
объект в `PROJECTS` — вёртка, сетка и подписи уже готовы.

## Контраст и читаемость мелких подписей

`--ink-3` (подписи, метки, футер) затемнён с `#71736a` до `#666860`: на фоне
`#ece9df` контраст был 3.96:1 при размере 10.5 px, то есть мелкие надписи вроде
«© 2026» читались вполсилы. Сейчас минимум 4.65:1 на всех светлых поверхностях
сайта — Lighthouse перестаёт считать это нарушением. На тёмных подписях
(`cal__label`, `cal__foot`, `demo__point-num`) прозрачность поднята с
0.45–0.55 до 0.55–0.62 по той же причине.

## Навигация без якорей

Пункты меню — это `<button>` без `href`: клик плавно скроллит страницу к секции
и ставит на неё фокус (`focus({ preventScroll: true })`), **URL не меняется** —
в адресной строке нет `#top`, `#design`, `#services`. Логотип возвращает к
позиции 0 без перезагрузки. Учтены фиксированная шапка (через `scroll-padding-top`),
закрытие мобильного меню по Escape (фокус возвращается на кнопку меню)
и `prefers-reduced-motion` (скролл становится мгновенным).

## Деплой

Хостинг — **GitHub Pages** (репозиторий `MindStyle1/Waystroke`, workflow
`.github/workflows/static.yml`), адрес: <https://waystroke.online>

Почему не Cloudflare Pages: `pages.dev` из части сетей без VPN не открывается.
Cloudflare в проекте остался только как DNS и как приёмник событий.

- Источник — GitHub `MindStyle1/Waystroke`, ветка `main`: каждый push в `main`
  собирается и публикуется автоматически (Actions → Pages).
- **Сборка**: `npm run build -- --base-href=/`. Именно `/`, а не `/Waystroke/`:
  кастомный домен отдаётся из корня, и с префиксом репозитория пути к js/css
  уезжали бы в подпапку и сайт открывался пустым.
- **Артефакт**: `dist/waystroke-studio/browser`.
- `.nvmrc` поднимает Node до 22.23.2 — облачный образ по умолчанию даёт 22.16.0,
  а Angular 22 требует ≥ 22.22.3.
- **SPA-fallback**: `postbuild` кладёт копию `index.html` в `404.html`, поэтому
  прямое открытие любого адреса рендерит приложение. Catch-all-правило
  `/* /index.html 200` в `_redirects` Cloudflare отклоняет собственной валидацией
  («infinite loop detected»), а `/* /404.html 200` на практике закольцовывает
  ответы (308 → `/404` → …) — поэтому используется только `404.html`.
- **DNS** (зона `waystroke.online`, NS Cloudflare): apex — четыре A-записи
  `185.199.108–111.153`, `www` — CNAME на `mindstyle1.github.io`, всё в режиме
  «только DNS» (серое облако, без прокси). MX и TXT Timeweb сохранены.
  Сертификат для обоих имён выпускает GitHub автоматически.
- **Cloudflare Pages** (проект `waystroke`) не удалён: `waystroke.pages.dev`
  продолжает собираться и открываться, но больше не обслуживает
  `waystroke.online` — это осознанный запасной адрес.

### Cloudflare Web Analytics

Beacon лежит в `src/index.html` с тем же токеном, который раньше подставлял
сам Cloudflare Pages. Как только сайт уехал на GitHub Pages, вставки от Pages
больше нет — без снимка в исходниках аналитика молча перестала бы собирать
всё, включая обычные посещения.

### Worker приёма конверсий

`worker/track.js` живёт на собственном имени `track.waystroke.online`
(Worker custom domain), а не на пути `/api/*` сайта. Причина та же: маршрут
`waystroke.online/api/*` работает только на проксированном трафике, а apex
теперь уходит на IP GitHub мимо Cloudflare. Свой домен остаётся на прокси,
поэтому Worker на месте; события приходят к нему с чужого источника, и в
обработчике появились CORS-заголовки с ответом на preflight.

## Проверено

- Desktop 1440×1000 и mobile 390×844, 360×800: без горизонтальной прокрутки
  и наложений
- CLS = 0 на 360×800 и 1440×1000 (`PerformanceObserver` по `layout-shift`
  с буфером, после прокрутки всей страницы)
- Lighthouse 12 (собранная версия, локальный сервер): mobile —
  Performance 64–68 (разброс прогона) / Accessibility 100 / Best practices 96 /
  SEO 100, desktop — 97 / 100 / 96 / 100, CLS = 0 в обоих. Мобильные 64–68 — это
  сервер без сжатия: на боевом хостинге страница отдаётся с brotli и сейчас
  даёт 83. В консоли только CORS-ошибка beacon'а — на `127.0.0.1` он и должен
  отклоняться, на `waystroke.online` отправляется
- `uses-responsive-images` на desktop: ~14 КБ на фотографии концепта внутри
  ползунка. Оставлено как есть — это демонстрационный макет с `loading="lazy"`,
