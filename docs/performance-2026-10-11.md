# Проверка производительности Waystroke — 11 октября 2026

## Вывод

Запрос касался просадок при скролле на компьютере в Firefox. Обнаружена
нестабильность одного из трёх прогонов Firefox; устойчивого замедления всех
прогонов не обнаружено. Исправлены два конкретных места без изменения дизайна.
Изменения подготовлены к публикации на waystroke.online по запросу пользователя.

## Подтверждённые проблемы и исправления

1. `src/index.html`: Cloudflare Analytics был подключён как модуль без `async`.
   При задержке этого ресурса на 5 секунд задерживался и запуск Angular.
   Медиана события `waystroke:app-ready` за три прогона Chromium: 5055 мс
   в исходном варианте, 276 мс с независимой загрузкой аналитики. Видимый
   статический текст появлялся раньше; это измерение готовности интерфейса,
   а не LCP. Заменено подключение аналитики на классический `async`.
   Проверка реальной локальной сборки после изменения: app-ready 410/284/244 мс
   с той же искусственной задержкой аналитики. Аналитика не удалена.
2. `src/app/scroll-motion.ts`: после разового появления все шесть карточек
   сохраняли inline `clip-path` и `transform`. После завершения tween эти
   свойства теперь очищаются через GSAP `clearProps`. Разовая анимация
   сохраняется; финальное положение, размер и дизайн не меняются.
   Проверка Firefox: оставшихся масок 6 до исправления, 0 после.

## Условия и измерения

- Опубликованная версия: https://waystroke.online/, commit 5160f13.
- Локальная версия: http://localhost:3000/, production build Angular 22.2.
- Firefox 156.0 через Playwright, headless, 1440×1000, обычный CPU без
  эмуляции замедления. Это отдельный контролируемый браузер, не личная сессия
  пользователя. Реальное GPU-поведение личного Firefox не установлено.
- Три последовательные пары «опубликованная версия / локальная правка».
  До прокрутки загружены шрифты и проиграны появления; курсор над витриной.
  50 wheel-событий по 100 px с паузой 100 мс плюс завершение инерции.
  Аналитика в scroll-тесте заблокирована в обоих вариантах, чтобы её сеть
  не влияла на сравнение. Интервалы измерены через requestAnimationFrame;
  это диагностические кадры страницы, а не аппаратный замер FPS экрана.

| Прогон | Firefox: p95 кадра до, мс | После, мс | Кадры >33,4 мс до / после |
|---|---:|---:|---:|
| 1 | 17,12 | 17,16 | 10/384 / 3/395 |
| 2 | 83,24 | 17,18 | 67/312 / 6/393 |
| 3 | 17,14 | 17,14 | 8/387 / 5/396 |

В двух из трёх исходных прогонов p95 и так был около 17 мс. Медиана p95
практически не изменилась. Один плохой прогон не повторился после изменения,
но это не доказывает, что вся разница вызвана очисткой масок.

Системный замер в ходе проверки: около 15,8 ГБ RAM, 4,75 ГБ available,
7,7 ГБ занято в swap; за один интервал vmstat зафиксировал swap-in 556 КБ/с.
Это данные всей системы во время лабораторного теста, не потребление памяти
сайтом и не доказательство состояния системы в момент жалобы. Нагрузка памяти
могла влиять на нестабильность результатов.

Дополнительные Chromium-прогоны 1440×1000 с CPU slowdown 4×:
- Маска / принудительно отключённая маска: p95 около 16,8 мс в обоих вариантах.
  Медиана суммарного Paint за сценарий 667 / 569 мс, но наблюдался разброс.
  Это диагностическая нагрузка, не доказанный прирост реального FPS.
- Проверка hover / отключённый hover не показала устойчивого улучшения:
  hover не изменён на основании неподтверждённой гипотезы.

DevTools: один повторный, тёплый navigation trace опубликованной версии
на 908×895, CPU 1×, без сетевого throttling: LCP 204 мс, CLS 0.
Мобильный тёплый trace 390×844, CPU 4×, Slow 4G: LCP 541 мс, CLS 0.
Кэш не очищался: эти результаты не оценивают холодную загрузку по мобильной
сети. CrUX не предоставил данных для страницы; выводы о полевых Core Web Vitals
и реальных INP не делались.

## Верификация и границы

- Production build, prerender checks и 44 теста прошли.
- Chromium: все шесть просмотров на desktop и ширине 390 px, Escape,
  возврат фокуса, снятие блокировки прокрутки, reduced motion.
- Firefox: открытие новых автосервиса и saldo на desktop, Escape,
  мобильный просмотр saldo без горизонтального переполнения.
- Системная нехватка памяти искусственно не создавалась; утечка памяти сайта
  не установлена. Постоянные 60 FPS на устройстве пользователя не гарантируются.

Исходные диагностические артефакты этой сессии: `/tmp/waystroke-load-trace.json.gz`,
`/tmp/waystroke-mobile-load.json.gz`, `/tmp/firefox-scroll-results.json`.
